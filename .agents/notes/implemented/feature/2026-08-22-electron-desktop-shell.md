# Agent Note: Electron desktop shell — supervised `dsh web` carriage, frame-pipe IPC delivery

Status: implemented

English | [中文](2026-08-22-electron-desktop-shell.zh.md)

## Problem

The web UI needs a windowed, standalone desktop application. The frontend is not standalone — only the Node server injects `window.__DSH_BOOT__`, serves `/api/*`, and carries the WebSocket downlink ([GUI layering](../architecture/2026-07-19-gui-layering-and-rpc-protocol.md)) — so a desktop app must run that server somehow. The layering note reserves an endgame design (an Electron shell reusing the client packages over an IPC fetch carrier, no ports), but nothing of that shell existed, and shipping it in one step would front-load its hardest parts before any native window exists.

## Decision

### A thin Electron shell supervising the real `dsh --profile web` surface

[`apps/desktop`](../../../../apps/desktop/README.md) (`@deepseek-ai/dsh-desktop`) spawns the shipped `dsh --profile web` surface as a supervised child — source launches pass `--carrier stdio`, so the child binds no socket, and `DSH_DESKTOP_CARRIER=tcp` restores a loopback listener for diagnosis — then parses the readiness line the web-app bundle prints after Loader settlement (`dsh web-stdio: ready`; tcp mode prints `dsh web: <url>`). The renderer is the ordinary web client, but its API traffic rides the IPC carrier rather than any network stack: the preload installs a `__DSH_IPC_CARRIER__` seat, the connection package selects `DesktopIpcApiClient` plus a bridge-backed Connection RPC caller when present, and the shell forwards unary requests to the supervised child while pumping both event streams as ServerRequest JSON text over per-stream IPC channels — wire shapes byte-identical to the WebSocket carrier. The seat also carries an optional native directory chooser answered by the shell's dialog (`dialog.showOpenDialog`) — the Host's OS-chooser backends have no macOS dialog — which the workspace runtime prefers whenever the bridge exposes it, falling back to the `host.pickDirectory` RPC elsewhere. The window loads `dsh://app/`, a privileged custom scheme whose main-process handler forwards HTML, static bundles, boot manifest, and plugin packages to the child — the renderer never sees a transport endpoint, and composition ownership stays untouched. The shell still adds zero model-visible content and zero session-log events.

### Frameless window chrome and the desktop contract with the client

The window is frameless-but-native (`hiddenInset` on macOS, `hidden` elsewhere): content sits flush with the top edge, Codex-style. The client marks its header rows (sidebar brand row, conversation header, details header) with `data-dsh-window-drag` — an inert attribute in browsers — and the shell injects the stylesheet that turns them into the drag region while `no-drag`-ing every interactive descendant. Two shell-owned refinements shape the top zone without reserving any layout: the brand row carries the `brand` attribute value so the shell can drop it below the traffic-light / window-control band (its own padding is the draggable air), and a 6px transparent edge across the window top drags from either column even while the session header hides for the blank hero. Platforms left without native controls receive a small injected overlay wired through a sandboxed preload bridge; that bridge is the shell's only IPC. The standard application menu supplies the Edit roles macOS needs to deliver Cmd+C/Cmd+V into the composer at all.

Drag-and-drop attachment and clipboard paste need no desktop code: both are client features (document-level drop handlers and composer paste) that the window inherits once file-navigation is suppressed.

The supervision seam is four modules, each with a single contract: launch-target resolution (`launch.ts`), readiness parsing (`readiness.ts`, a pure function), process lifetime (`server-process.ts`: spawn → readiness → bounded SIGTERM→SIGKILL escalation; failures carry an output tail; post-readiness death fails loud through a modal dialog), and a parent-death watchdog (`watchdog.ts`). The watchdog exists because Chromium reaps externally delivered SIGTERM/SIGINT before Electron's JavaScript runs any handler — teardown therefore cannot depend on this process staying alive. A stock-Node wrapper owns the server and polls its parent once per second, so a crash, SIGKILL, or signal kill of the shell still tears the tree down within roughly one second. Lifecycle rules: quitting closes window **and** server on every platform including macOS (a dock-resident shell with a dead backend serves only connection errors); single-instance lock focuses the existing window.

Launch targets are a seam, not a hardcode. Repository checkouts source-launch through tsx exactly like `pnpm dsh`. The packaged form ships the harness runtime as a materialized deploy of a dependency-only manifest (`apps/desktop/closure/package.json` — the same shape as the Python SDK runtime's deploy root) under `Resources/dsh-runtime`, and launches it with `ELECTRON_RUN_AS_NODE=1`: Electron's own binary doubles as plain Node, so no second runtime rides inside the bundle, and `@electron/rebuild` gives `node-pty` Electron's module ABI inside that closure. `DSH_DESKTOP_SERVER_BIN` remains the escape hatch for an external `dsh` executable; all shapes accept identical flags, so packaging changes configuration, not architecture.

### Staging toward the reserved IPC-carrier design

Phase 2 swapped the carriage without touching the shell's lifecycle code. An `AbstractApiClient` subclass (`desktop-carrier.ts` in dsh-client-connection) implements `doFetch`/stream virtuals over an injected bridge object, and the delivery side is the stdio carrier: `dsh-host-webserver` exposes `serveStdio`, which drives the identical route dispatch over NDJSON frames on the child's stdin/stdout — the app assembly selects it with `dsh web --carrier stdio`: `web-startup` publishes `carrier`, the bundle's webserver row forwards it, stdio mode skips the bind, fds 3 (frames in) and 4 (frames out) keep stdout/stderr as pure logs, and the readiness line becomes `dsh web-stdio: ready`. The desktop shell adopts it as its default: the supervisor passes both frame pipes through the watchdog (macOS closes fds above 2 across `posix_spawn` without an explicit inherit), a parent-side `FrameChannel` demultiplexes responses by id onto the same forwarders the tcp mode used — unary fetches, SSE stream pumps, and the app-scheme protocol handler all answer from one channel — and the real-boot smoke asserts the child serves everything with no listening socket. Two wire facts keep the browser-trust fence and stream teardown honest on this transport: `serveStdio` binds a headerless frame's Host to `127.0.0.1` (the supervisor pipe is the trust anchor — browsers cannot send Host, the renderer sends none, an explicit Host passes through so spoofed authorities still fail closed), and a disposed stream subscription writes an `{id,t:'cancel'}` control frame that makes the child destroy the response, unwinding its SSE generator instead of pumping frames nobody reads; correspondingly the shared fetch handler serves the events paths as SSE when the webserver runs the stdio carrier, reserving the 426 upgrade-required answer for transports that actually have a socket to upgrade. The reserved destination, no socket or port anywhere in the renderer's path, is thus reached with frame pipes; MessagePort framing stays open only if a future need appears. The transitional tcp carrier remains as a diagnostic fallback (`DSH_DESKTOP_CARRIER=tcp`).

## Alternatives considered

**In-process assembly inside Electron main.** Importing `app-boot` and replicating `runProfile`'s patch stack duplicates launcher semantics in a second owner; importing apps/cli from another app breaks the applications-never-load-each-other rule. It would also load `node-pty` into Electron's Node ABI immediately, forcing `@electron/rebuild` before anything user-visible ships.

**Tauri wrapping the URL.** Same spawning model, but introduces a second shell technology for the same job and still requires the sidecar binary; Electron keeps main-process tooling in one language we already ship.

**Going straight to pure IPC.** No transitional mode to retire later, but the stream carrier (MessagePort framing for mux/host streams), custom-protocol bundle delivery, and ABI rebuild all land before the first runnable artifact. Rejected as a first step; kept as the destination.

## Consequences

**Bought**: a native windowed app whose behavior is byte-identical to `dsh web` (same bundle stack, user patches, HMR watch, trust fence); a four-module seam where every desktop-specific decision lives; local packaging (`pnpm run package`) producing installable macOS/Linux artifacts whose runtime is configuration, not a redesign; a per-app log file that keeps the supervised child's output readable without a launching terminal.

**Paid**: one extra OS process and a loopback port during Phase 1, plus the tiny stock-Node watchdog process between shell and server; Windows stays out of scope with the CLI's other surfaces; the Electron runtime (~100MB installed) rides along even though the shell code is small; release signing, notarization, per-target CI legs, and designed icons remain open distribution work.

## Required verification

Unit specs cover the seam modules (`apps/desktop/tests/*.spec.ts`), including real-process watchdog tests whose harness spawns the five-stdio-slot shape production uses (the watchdog's inherit needs fds 3/4 to exist, or its inner spawn dies with `EBADF`): signal forwarding kills the fake server, and an orphaned watchdog (parent SIGKILLed) tears its own child down within the poll interval. Post-readiness death reports fire for both carrier kinds — readiness itself gates the report, since a stdio child has no URL. The request/response members the node↔fetch bridge reads (async-iterable body, `writableEnded`, `destroy`) are pinned in dsh-host-webserver specs and exercised end-to-end over the real frame stack in a dsh-client-connection spec; those specs also pin the loopback Host binding, the cancel-frame teardown (both codec sides), and — against the composed plugin in stdio mode — SSE mux streaming with cancel-driven unwind plus fence refusal of a spoofed Host. A real-boot smoke (opt-in via `DSH_DESKTOP_SMOKE=1`, because it needs built workspace libs and the frontend dist while unit tests must pass on a clean tree) spawns the actual source-launched surface under the watchdog against an isolated temp `DSH_HOME`, asserts the stdio readiness line and that no listening socket exists, serves `/` through the frame channel and finds the injected `__DSH_BOOT__`, performs one real unary RPC through the trust fence (`host.describe`), opens and cancels the mux events stream over frames, then requires exit code 0 after the supervisor's SIGTERM. Live verification additionally killed the running Electron app externally and confirmed no server process survived.
