# Agent Note：客户端工作台栏——左侧可展开视图面

Status: implemented

[English](2026-08-22-client-workbench-column.md) | 中文

## Problem

框架此前只有三个固定栏（侧边栏 | 中栏 | 详情栏），没有给持久工作面留出位置——diff 审阅、代码查看、图片检查以及未来的内嵌浏览器都需要一个跨会话切换存活的左侧区域。没有它，每个此类功能都只能自行发明面板管线，或与随会话作用域关闭的详情栏契约冲突。

## Decision

[`packages/client/ui-layout`](../../../../packages/client/ui-layout/README.md) 由同一让步链求解器渲染四轨道网格（`sidebar | workbench | center | details`），其让步顺序为：详情栏先向最小值收缩并自动关闭；随后工作台才向其最小值收缩（绝不会高于自身偏好——关闭详情栏可能已释放足够空间，使工作台无需让步）并自动关闭；剩余缺口最后由中栏吸收。派生的关闭绝不改写存储的偏好宽度，因此窗口重新变宽时会自动恢复。

`workbench` 子 slot 由根注册与兄弟 slot 一同声明，为 root 作用域以使该栏跨会话切换存活，并携带镜像侧边栏实时让步输出的 `collapsed`/`width` 所有者份额。单 slot 语义在未被占用时不渲染任何内容，因此该栏不可见——面板动作也只是视觉上的空操作——直到某个功能在此注册认领它。布局 store 新增 `workbench` 宽度偏好（0 = 关闭），动作纪律与其兄弟一致（`setWorkbench` 钳制在 320–560 契约区间；open 仅在关闭态写入 400 默认值；close 归零），且 `ctx.layout` 扩展出 `openWorkbench()`/`closeWorkbench()`，任何插件的 apply 世界都可直接驱动该栏而无需触达 store。可发现性由框架负责：栏关闭时，侧边栏接缝上的一个细长页签（`workbenchToggle`，箭头可供性，带 aria 标签）以契约默认值打开它——这是必需的，因为零宽度下不存在拖动手柄——而打开状态下双击其手柄会再次关闭。首个预期的占用者是交互式终端；diff 与代码查看器随后跟进。

## Alternatives considered

**把视图挂进现有详情栏或侧边栏内部座位。** 否决：详情栏在右侧且随会话作用域关闭（每次切换会话都会关闭），而侧边栏的内部座位组合的是导航而非工作面——两者都会与其现有契约冲突。

**覆盖层或弹出层。** 否决：工作台内容是持久的工作上下文，而非瞬时装饰；`shell.overlay` 刻意保持点击穿透且无归属。

**在侧边栏内部做一个可折叠分区。** 否决：它会把视图托管耦合到导航状态，并把轨道折叠契约拖入视图管理；平级轨道让两栏在同一求解器下独立缩放。

## Consequences

注册进 `workbench` 的功能继承框架的几何契约：它们必须容忍零宽度挂载（关闭时子树保持挂载）、从所有者份额而非 store 偏好读取宽度，并通过 `ctx.layout` 而非本地状态驱动可见性。让步链多了一个参与者，因此对同时打开两个侧面板的组合而言，面板挤压行为发生变化——详情栏总是先让步。

## Testing

求解器规格覆盖每个让步步骤，包括详情优先的顺序、"收缩不超过偏好"规则、自动关闭后的恢复以及退化视口；store 规格钉住初始化形状、钳制区间、默认打开/关闭生命周期与不持久化；frame 规格钉住四轨道模板、所有者份额传递、位于 sidebar+workbench 处的手柄及 +dx 增宽、详情让步关闭而工作台存活的挤压场景、以及关闭态页签按默认值打开与手柄双击关闭；service 规格钉住新面方法的委托。
